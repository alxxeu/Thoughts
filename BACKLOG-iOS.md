### Единое звёздное поле для Spoiler/Lock — сначала Mac, замеры (план согласован 2026-10-18)

него (маска по её рамке), как на Space Lock; звёзды скользят по заблокированным
карточкам — «void». На iPhone нынешний CAEmitterLayer выглядит дёшево, не как на Mac.
- [x] 1. Замер-основа на Mac: Debug с `-demoBoard YES` (отдельная доска, без iCloud),
  ~12 Spoiler/Lock карточек на холсте; xctrace Time Profiler, процессор без жестов.
- [x] 2. Прототип на Mac: один StarFieldCanvas на весь холст над карточками, маска —
  скруглённые рамки заблокированных карточек (позиции и размеры из BoardViewModel, без
  замеров геометрии) минус рамки незаблокированных карточек выше по z; мягкий край как
  сейчас; под маской тот же затемняющий тон.
- [x] 3. Повторный замер, сравнение, решение.
Результат замеров (Mac, демо-доска, 10 Spoiler/Lock карточек, простой, процессор по `top`):
- как сейчас (поле на карточку): ~22% ядра; главный поток: рисование звёзд 158, слои RBLayer 582 из ~2100 замеров.
- общий Canvas на весь холст + маски (прототип): ~22%; рисование звёзд 969, RBLayer 168 — переехало, не исчезло:
  цена Canvas идёт по площади поверхности, а не по числу звёзд.
- Canvas(rendersAsynchronously: true): суммарно те же ~22% (работа ушла в фоновый поток, но осталась).
Вывод: общий Canvas выигрыша не даёт; прототип лежит в `git stash` («shared-canvas star field prototype»).
Следующий вариант: звёзды как CALayer с анимациями Core Animation (дрейф и мерцание
считает рендер-сервер, а не процессор приложения) — один слой на окно + маска; один код

### Живой Markdown в редакторе iPhone (план согласован 2026-10-17)

Запрос: никаких `**`, `#`, `-` на экране — текст сразу выглядит оформленным;
панель Markdown — крупные одинаковые значки; ссылка — попап (поле + Cancel/Add);
добавить блок кода.
- [x] 1. Свой редактор вместо TextEditor: UITextView (TextKit 1) в
  UIViewRepresentable; шрифт, поля, размытие под шапкой, тёмная клавиатура,
  тап в текст → Full, как сейчас.
- [x] 2. Отрисовка — порт Mac `MarkdownRenderer` + `MarkdownBlockDecorator` на
  UIKit по общему `MarkdownStyler.parse`: заголовки, жирный/курсив/зачёркнутый/
  подчёркнутый/выделенный, код строкой и блоком (моно + подложка), цитата
  (полоса), список (•), чек-лист (квадратик, тап — отметить), ссылки, `---`.
- [x] 3. Служебные символы скрыты всегда (на Mac — видны у курсора; на iPhone
  — нет, решение пользователя). Курсор не встаёт внутрь скрытых символов,
  Backspace у границы стирает видимый символ, а не `*`. Набранный руками
  Markdown (`**a**`, `# `, `- `, `> `, ```` ``` ````) сразу превращается в
  оформление.
- [x] 4. Панель: один набор SF Symbols одного веса, 20 pt, касание 44 pt; две
  группы (строка / блок); активный стиль подсвечен.
- [x] 5. Ссылка: попап с полем URL (и текстом, если ничего не выделено),
  Cancel / Add.
- [x] 6. Блок кода: кнопка оборачивает выделенные строки в ```` ``` ````
  (повтор — снимает); `MarkdownFormatting` + тесты.
- [x] 7. Тесты чистой логики (обход скрытых символов, блок кода); проверка в
  симуляторе и на iPhone; спека и бэклог.
Риски: русская клавиатура с автоисправлением рядом со скрытыми символами;

### iPhone-компаньон — продуктовые решения (обсуждение 2026-10-15)

Роль: Mac — стол, iPhone — карман: быстро записать и подсмотреть. Референсы
в Figma-файле «Thoughts» (Capture, папки и чат Telegram).
- Space = чат, карточка = сообщение. Поле ввода внизу — только текст, без
  «+» и микрофона. Новое — внизу, у поля ввода.
- Spaces — вкладки сверху и свайп между ними, как папки в Telegram.
- Каждая карточка — отдельный блок (не слитые через тонкую полоску).
- Порядок: по `contentModifiedAt` (последняя правка текста, на Mac или
  iPhone), свежие ближе к полю ввода. Галочки чек-листа — тоже правка.
  Карточки без даты (`unknownDate`) — в порядке холста Mac: сверху вниз,
  слева направо. Лента не перестраивается под пальцем — новый порядок при
  открытии Space / возврате из карточки, с анимацией.
- Превью в ленте: минимум ~2 строки, максимум ~8–10 с затуханием; целиком —
  в редакторе по тапу. Тег — точка в углу; Spoiler — звёздный блюр в тех
  же пределах; Lock — минимальная высота и замок.
- Теги, Spoiler, Lock меняются только внутри редактора карточки; на
  карточке в ленте — только их отображение.
- Нет на телефоне: Tidy Cards, Clear Space, Ask AI по Space, холст.
- **Дополнение 2026-10-15: iOS — самостоятельный продукт.** Без Mac и без
  синка iPhone — полноценные заметки; Mac и синк — дополнение. Рамка «Mac —
  стол, iPhone — карман» пересматривается в docs/ios/SPEC.md. Фокус —
  необходимый минимум (экспорт/импорт — позже); онбординг намекает, что
  лучше вместе с Mac.

### Лаги при закрытии клавиатуры — разбор 2026-10-18
Time Profiler на iPhone 15. Причины, найденные и убранные: пересборка сотен слоёв звёзд на каждый кадр (`StarVoidView.buildStars` — теперь один раз на размер экрана) и опрос глобальных рамок у всех карточек (теперь только у скрытых). Самые длинные непрерывные занятости главного потока: 440 мс → 85 мс, зависаний ≥100 мс: 17 → 0. Остаток (60–85 мс) — перекладка SwiftUI при смене высоты ленты и работа системной клавиатуры; `GlassEffectContainer` пробовали — выигрыша нет, убран. Если лаги останутся: стекло карточек (~13% главного потока), создание `UITextView` в `MarkdownLabel` (заменить на лёгкий UIView с отрисовкой через NSLayoutManager).
Дополнение: главная причина — ленты всех Spaces были собраны сразу и каждая перекладывалась при смене высоты. Теперь собраны текущий Space и соседние (дальний переход и так ставит цель рядом). Замер: загрузка главного потока в жестах 55% → 43%, занятость ≥50 мс: 35 → 12, ≥100 мс: 0. Оставшиеся длинные куски — запуск приложения и системное появление клавиатуры (`setInputViews`). Стекло карточек и `UITextView` в `MarkdownLabel` не менялись — не главное.
Пробовали держать живой только текущий Space, пока открыта клавиатура: средняя загрузка ниже (39%), но пересоздание страниц даёт пики 100–118 мс — откатили. Оставшееся закрытие клавиатуры: синхронная перекладка SwiftUI ~45 мс (`UICoreKeyboardTracking` → `layoutSublayers`) + стекло ~13% главного потока. Идеи на потом: ScrollView с постоянной рамкой и `contentMargins` под клавиатуру; облегчить стекло карточек.
Эксперимент «карточки без стекла»: нагрузка 43% → 37%, самый длинный кусок 81 → 61 мс, зависаний ≥50 мс 12 → 11 — стекло не главная причина, оставлено. Нижнее затухание — только градиент (без `thinMaterial`). Остаток: при каждом показе/закрытии клавиатуры UIKit (`layoutBelowIfNeeded`) синхронно перекладывает весь SwiftUI-экран, 40–60 мс. Чтобы убрать: лента с постоянной рамкой (`ignoresSafeArea(.keyboard)` + ручной отступ под клавиатуру) — большая переделка, пока не берём.
Чёрная полоса при показе/закрытии клавиатуры (по видео владельца): поле ввода уезжало быстрее клавиатуры, потому что состояние `typing` анимировалось своим `.snappy`, а клавиатура — своей кривой; между полем и клавиатурой оставался зазор с тёмным затуханием. Теперь `typing` без своей анимации, панель едет только в анимации клавиатуры (сжатие поля — отдельно по `compact`). Проверено владельцем: полоса ушла.
Главная находка: корневой `GeometryReader` в `FeedScreen` перестраивал весь экран (все ленты, карточки) на каждый кадр анимации клавиатуры, потому что менялся нижний отступ. Заменён на `onGeometryChange` только по верхнему отступу. Замер: непрерывных занятостей ≥33 мс 32 → 4, ≥50 мс 12 → 0, самая длинная 81 → 48 мс. Идея на потом, если понадобится: вынести `bottomBar` в отдельный `View`, чтобы смена `typing` не пересчитывала ленты.
ОТКАТ (2026-10-18): замена корневого `GeometryReader` на `onGeometryChange` сломала отображение карточек и оставляла Spaces-панель при открытой клавиатуре на устройстве — коммит откачен. Профиль улучшался, но без проверки глазами на устройстве такие правки не коммитить.

## Нативная механика поля ввода и клавиатуры — исследование (Правило 7, 2026-10-18)
Изучено (вывод — решение пользователя пока ждёт):
